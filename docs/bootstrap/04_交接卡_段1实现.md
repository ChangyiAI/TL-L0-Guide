## 假设（V3～V16）

- **V3**：单包核对采用“包存在性（1）→ 签字链（5）→ 清单结构（2）→ 清单自洽（3）→ 签字及文件状态”的保守顺序；按任务仍按 `5 ＞ 3 ＞ 2 ＞ 4` 汇总。
- **V4**：非 Windows 平台的默认 `C:\TianlongSign` 不是绝对路径，涉及签字目录时判 1，不把它解释为当前目录。
- **V5**：仅实际需要签字目录的 `sign`、`verify`、`status` 校验 `TL_SIGN_DIR`；仅写时间的 `pack`、`sign` 校验 `TL_NOW`。`TL_NOW` 空串按未设置处理，使用当前带时区时间。
- **V6**：确认命令只要显式提供 `--reason`（包括空串）即判 1，避免调用语义含混。
- **V7**：并发 pack 用独占创建逐号重试；sign 用锁文件串行化，不能把一次概率性并发测试通过当作安全证明。
- **V8**：任何已有签字（含退回）的包若清单缺失，按任务核对均判 3。
- **V9**：仓库根只按逐级查找首个 `.git` 判定，不读取 Git 环境变量；临时目录若恰位于另一仓库内，应由测试环境隔离解决。
- **V10**：在仓库子目录运行 pack 时，相对的正文和附件路径按当前工作目录解析，再核对解析结果位于仓库内。
- **V11**：“签过”包括已确认和退回；签后内容变化均显示“签后文件已变”。
- **V12**：签字文件无法打开或写入时判 1 并给中文原因；Windows 文件占用留给本机人工实测。
- **V13**：签字记录的 `manifest_sha256` 必须是 64 位小写十六进制，否则按记录损坏判 5。
- **V14**：任务 `packages/` 下名字不是合法包编号的 JSON 视为清单结构不合格，按 2 处理，而不是用法错误。
- **V15**：签字记录先做完整字段和链式校验，再判断重复签字；缺完整指纹本身即足以判 5。
- **V16**：不带 `--task` 的 status 同样检查每个清单结构；任一不合格则整体判 2，并在对应包行显示“清单不合格”。

## 假设（W1～W8）

- **W1**：非 Windows 平台保留文件系统的大小写语义；Windows 才对真实路径分量做不分大小写且去除末尾点和空格的比较。
- **W2**：链条断开时，保守地把能识别出包编号的所有签字记录都视为相关，对应包均标“签字记录损坏”。
- **W3**：“待签包数”按 5.1 原意解释为尚未签字的包数，不是包总数。
- **W4**：`TL_NOW` 先用统一正则限定写法，将 `Z` 显式换为 `+00:00` 后再解析，不依赖 Python 版本对 `Z` 的差异。
- **W5**：`status` 读签字文件遇权限类错误也判 1；这与“status 只返回 0、1、2”一致。
- **W6**：Windows 独占建锁遇 `PermissionError`（拒绝访问）统一当作锁被占用并等待；非 Windows 不扩大这个特例。
- **W7**：凡是需要定位签字文件的 `sign`、`verify`、`status` 都执行签字根目录与最终签字文件目录的双重边界检查。
- **W8**：只要读签字文件收到权限类错误，就按“签字文件被占用”判 1；Excel 真实独占情形不用容器结果替代 Windows 人工实测。

## 审 AI 三问

### 1. 最难的判断是什么？

最难的是把“命令输入错误、记录结构错误、指纹变化、未签状态、签字记录损坏”五类失败按不同命令规定的先后顺序拆开。实现没有用一个笼统异常吞掉差异；单包核对和按任务汇总分别执行裁定顺序。

第 11 节新增的最难判断是让 `status` 在严格签字解析已判 5 的情形下仍安全地做有限度容错：它只提取可归属的包编号用于显示“签字记录损坏”，不把损坏记录当成有效授权。

### 2. 否决了哪些看似更简单的方案？

- 否决调用 `git rev-parse`：仓库根完全由 Python 从当前目录向上查找 `.git`，避免外部程序劫持及 Git 环境变量影响。
- 否决信任 pack 生成过的清单：sign、verify、status 每次都重新做编号、任务、角色、路径与链接边界校验。
- 否决普通覆盖写与无锁追加：pack 使用独占创建；sign 持锁后重读链条，追加后 `flush`、`fsync`。
- 否决只保存 8 位展示码：签字记录保存并核对完整 64 位清单指纹。
- 否决让 `status` 直接调用严格签字读取并返回 5：改用只供展示的容错读取，且损坏记录不参与“已确认”判定。
- 否决直接依赖 `datetime.fromisoformat` 接受 `Z`：先规范化为 `+00:00`，保证 Python 3.10 与后续版本一致。

### 3. 目前最没把握的地方是什么？

跨平台文件锁语义仍最没把握，尤其是 Windows “删除进行中”的拒绝访问窗口，以及签字文件被 Excel 等程序真实独占时的错误映射；这两项仍以 Windows 实测③为准。此外，段1的 `TL_SIGN_DIR` 是测试入口，正式推进安全仍依赖段2在受保护环境中清除全部 `TL_*` 后执行核对。
